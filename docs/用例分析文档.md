# 智能法务系统 — 用例分析文档

本文档依据软件工程用例分析方法，对智能法务系统的全部用例逐一进行规格化描述。每个用例从参与者、前置条件、后置条件、主事件流（参与者行为 / 系统行为）、备选事件流五个角度进行分析。用例按参与者分组，重复用例合并描述。

---

## 一、业务人员用例

### 用例 1.1  用户注册与登录

**参与者**：业务人员（法务人员、管理员、审计员共用）

**前置条件**：用户已访问系统首页；当前为未登录状态

**后置条件**：用户获得有效的 JWT 访问令牌；系统识别其身份和角色；前端将令牌持久化存储

**主事件流**

| # | 参与者行为 | 系统行为 |
|---|-----------|----------|
| 1 | 点击"登录"按钮，进入登录页面 | 展示登录表单（用户名、密码输入框） |
| 2 | 输入用户名和密码，点击"登录" | 在 `users_store.json` 中查找用户名；验证密码哈希值是否匹配 |
| 3 | — | 验证通过，生成 JWT 令牌（HS256 签名，有效期 480 分钟，含用户 ID 和角色）；返回令牌和用户信息至前端 |
| 4 | 前端接收令牌，存储至 `localStorage`；跳转至系统首页；后续请求自动附带令牌 | — |

**备选事件流**

| # | 描述 |
|---|------|
| 2a | 用户选择"注册"标签，输入用户名、密码和显示名称，点击"注册" |
| 2b | 系统校验用户名唯一性，对密码进行 BCrypt 哈希，创建用户记录（默认角色 `business`），返回注册成功 |
| 2a1 | 用户名已存在 → 系统提示"用户名已被占用" |
| 2a2 | 密码长度不足 6 位 → 系统提示"密码长度至少 6 位" |
| 3a | 用户名不存在或密码验证失败 → 系统提示"用户名或密码错误" |
| 3b | JWT 令牌过期（480 分钟后）→ 系统返回 401，前端清除令牌并跳转至登录页 |

## 二、法务人员用例

> 法务人员继承业务人员的全部权限（注册登录、上传合同、查看合同状态、法律咨询、法律检索），以下仅列专属用例。

### 用例 2.1  AI 合同审查

**参与者**：法务人员

**前置条件**：用户已登录且角色为 `legal` 或 `admin`；合同已上传且至少有一条已解析条款

**后置条件**：合同审查状态更新为"已审查"；条款填充风险等级、法律依据和修改建议；审计日志写入

**主事件流**

| # | 参与者行为 | 系统行为 |
|---|-----------|----------|
| 1 | 在合同详情页点击"AI 审查" | 检查合同 `clauses` 字段是否为空，若为空则先执行条款解析 |
| 2 | — | 从 `contracts_store.json` 读取合同全文和条款列表 |
| 3 | 可选：输入补充审查要求（如重点关注的条款或特殊风险类型） | 从 `prompts/` 加载 `contract_review.md` 模板，构建系统提示词（"资深合同律师"角色和输出格式约束） |
| 4 | — | 组装审查 Prompt（条款内容 + 审查规则 + 补充要求），调用 LLM API（`temperature=0.1`） |
| 5 | — | LLM 返回 JSON 格式审查结果：逐条标注 `risk_level`（high / medium / low / none）、`risk_analysis`、`law_basis`、`suggestion` |
| 6 | — | 解析 JSON，将审查结果填充至各条款对象 |
| 7 | — | 更新合同 `review_status` 为"已审查"，持久化至 `contracts_store.json` |
| 8 | — | 调用 `AuditLogger` 记录审计日志；返回审查报告（风险分布统计 + 逐条审查详情） |
| 9 | 查看审查报告；可点击单条条款展开详情 | — |

**备选事件流**

| # | 描述 |
|---|------|
| 3a | 用户选择审查范围（全部条款 / 仅高风险条款）→ 系统仅对选中范围的条款提交 LLM 审查 |
| 5a | LLM 返回的 JSON 无法解析 → 系统重试一次（附加"请严格输出 JSON 格式"指令）；重试仍失败则提示"AI 分析异常，请稍后重试" |
| 5b | LLM API 调用超时（> 60 秒）→ 系统返回"审查请求超时，请稍后重试" |
| 6a | 审查后用户逐条确认或修改 AI 建议 → 系统保存人工修正后的条款并标记"人工复核" |

| 3 | — | 逐条比对条款内容：形式差异（措辞、标点、格式变更）与实质差异（权利义务变更、责任分配变化） |

| 5 | — | 对实质差异项，调用 LLM 进行风险评估 |
| 6 | — | 返回比对结果（差异统计 + 逐项清单） |
| 7 | 查看比对报告；差异项以红/黄色高亮标注 | — |

**备选事件流**

| # | 描述 |
|---|------|
| 1a | 合同 B 尚未解析条款 → 系统先执行 `parse_clauses()` |
| 1b | 两份合同条款数量差异过大（> 5 倍）→ 系统提示"合同结构差异显著，建议人工比对" |
| 5a | LLM 风险评估失败 → 差异报告仍正常返回，仅实质差异项缺少风险评估标注 |

## 五、用例优先级汇总

**高优先级（核心业务）**

用户注册与登录、上传合同、AI 合同审查、合同条款比对、法律问题咨询、案件管理与分析、LLM 配置管理

**中优先级（重要支撑）**

查看合同状态、法律知识检索、AI 合同生成、知识图谱查询、文书模板管理、用户管理、系统参数设置、知识库初始化、查看审计日志、导出合规报告

**低优先级（辅助功能）**

法律计算工具、数据导出、按条件筛选日志、查看操作统计
