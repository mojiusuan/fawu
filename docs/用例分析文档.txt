智能法务系统 — 用例分析文档

本文档依据软件工程用例分析方法，对智能法务系统的全部用例逐一进行规格化描述。每个用例包含：用例名称、参与者、前置条件、后置条件、主事件流（参与者行为/系统行为）、备选事件流。用例按参与者分组，重复用例合并描述。

一、业务人员用例
══════════════════════════════════════

用例 1.1  用户注册与登录
────────────────────────
参与者      业务人员（法务人员、管理员、审计员共用）
前置条件    用户已访问系统首页；当前为未登录状态
后置条件    用户获得有效的 JWT 访问令牌；系统识别其身份和角色；前端将令牌持久化存储

主事件流
  参与者行为                                  系统行为
  ─────────────────────────────────────────  ─────────────────────────────────────────
  1. 点击"登录"按钮，进入登录页面             2. 展示登录表单（用户名、密码输入框）
  3. 输入用户名和密码，点击"登录"             4. 在 users_store.json 中查找用户名；
                                               验证密码哈希值是否匹配
                                             5. 验证通过，生成 JWT 令牌（HS256签名，
                                               有效期 480 分钟，含用户 ID 和角色）
                                             6. 返回令牌和用户信息至前端
  7. 前端接收令牌，存储至 localStorage；
     跳转至系统首页；后续请求自动附带令牌

备选事件流
  3a. 用户选择"注册"标签，输入用户名、密码和显示名称，点击"注册"
  3b. 系统校验用户名唯一性，对密码进行 BCrypt 哈希，创建用户记录（默认角色 business），
      返回注册成功
  3a1. 用户名已存在 → 系统提示"用户名已被占用"
  3a2. 密码长度不足 6 位 → 系统提示"密码长度至少 6 位"
  4a. 用户名不存在或密码验证失败 → 系统提示"用户名或密码错误"
  6a. JWT 令牌过期（480 分钟后）→ 系统返回 401，前端清除令牌并跳转至登录页


用例 1.2  上传合同
────────────────────────
参与者      业务人员
前置条件    用户已登录且角色为 business 或以上
后置条件    合同记录写入 contracts_store.json；条款列表完成解析；返回合同详情

主事件流
  参与者行为                                  系统行为
  ─────────────────────────────────────────  ─────────────────────────────────────────
  1. 在合同管理页面点击"上传合同"             2. 展示合同信息填写表单
  3. 填写合同标题；选择合同类型（买卖/租赁/      —
    服务/劳动/借款/其他）
  4. 输入甲、乙双方名称                        —
  5. 粘贴或输入合同全文内容                    —
  6. 点击"提交"                              7. 验证必填字段（标题、内容）非空；
                                               生成合同编号（UUID 前 8 位）；
                                               创建 ContractInfo 对象并持久化
                                             8. 调用 parse_clauses() 按条款编号拆分
                                               文本为 ClauseInfo 对象列表
                                             9. 返回合同详情（含合同信息与条款列表）

备选事件流
  5a. 用户选择上传 DOCX/PDF/TXT 文件 → 系统通过文档解析引擎提取文本并回填至输入框
  7a. 必填字段为空 → 系统提示"合同标题和内容不能为空"
  7b. JSON 文件写入失败（磁盘空间不足）→ 系统返回 500 错误

用例 1.4  法律问题咨询
────────────────────────
参与者      业务人员
前置条件    用户已登录；知识库已完成初始化
后置条件    咨询记录写入 consultation_history.json；审计日志追加至 logs/ 目录

主事件流
  参与者行为                                  系统行为
  ─────────────────────────────────────────  ─────────────────────────────────────────
  1. 在咨询页面输入框中输入法律问题              —
  2. 点击"发送"或按回车键                     3. 将问题路由至 ConsultationAgent
                                             4. Agent 启动混合检索：
                                                ChromaDB 语义向量检索（top 20）
                                                + Whoosh BM25 关键词检索（top 20）
                                             5. 两通道结果加权合并（语义 0.7+B M25
                                                0.3）、去重、按得分排序取 top 10
                                             6. 从 prompts/ 加载 legal_opinion.md 模板
                                             7. 将检索结果作为上下文注入模板，组装
                                                完整 Prompt 提交给大语言模型
                                             8. LLM 生成结构化回答（直接回答→法律依据
                                                →实操建议），每条依据标注法规条文
                                             9. 记录审计日志和咨询历史摘要
                                             10. 在对话界面展示 AI 回答，附引用法条
                                                列表和免责声明

备选事件流
  1a. 用户点击预设常见问题入口 → 系统自动填入问题文本
  4a. 用户选择检索范围（全部/法规/判例）→ 系统在检索时附加 where_filter 条件
  5a. ChromaDB 不可用 → 系统降级为仅 Whoosh 关键词检索，结果中标注"语义检索暂不可用"
  8a. LLM API 调用超时或返回错误 → 系统提示"AI 服务暂时不可用，请稍后重试"

用例 2.1  AI 合同审查
────────────────────────
参与者      法务人员
前置条件    用户已登录且角色为 legal 或 admin；合同已上传且至少有一条已解析条款
后置条件    合同审查状态更新为"已审查"；条款填充风险等级、法律依据和修改建议；审计日志写入

主事件流
  参与者行为                                  系统行为
  ─────────────────────────────────────────  ─────────────────────────────────────────
  1. 在合同详情页点击"AI 审查"                2. 检查合同 clauses 字段是否为空；
                                               若为空则先执行条款解析
                                             3. 从 contracts_store.json 读取合同
                                               全文和条款列表
  4. 可选：输入补充审查要求（如重点关注的      5. 从 prompts/ 加载 contract_review.md
     条款或特殊风险类型）                       模板，构建系统提示词（设定"资深合同
                                               律师"角色和输出格式约束）
                                             6. 组装审查 Prompt（条款内容 + 审查规则
                                               + 补充要求），调用 LLM API
                                               （temperature=0.1）
                                             7. LLM 返回 JSON 格式审查结果：
                                               逐条标注 risk_level（high/medium/
                                               low/none）、risk_analysis、law_basis、
                                               suggestion
                                             8. 解析 JSON，将审查结果填充至各条款
                                               对象的对应字段
                                             9. 更新合同 review_status 为"已审查"，
                                               持久化至 contracts_store.json
                                             10. 调用 AuditLogger 记录审计日志
                                             11. 返回审查报告（风险分布统计 +
                                                 逐条审查详情）
  12. 查看审查报告；可点击单条条款展开详情       —

备选事件流
  4a. 用户选择审查范围（全部条款 / 仅高风险条款）→ 系统仅对选中范围的条款提交 LLM 审查
  7a. LLM 返回的 JSON 无法解析 → 系统重试一次（附加"请严格输出 JSON 格式"指令）；
      重试仍失败则提示"AI 分析异常，请稍后重试"
  7b. LLM API 调用超时（>60 秒）→ 系统返回"审查请求超时，请稍后重试"
  8a. 审查后用户逐条确认或修改 AI 建议 → 系统保存人工修正后的条款并标记"人工复核"


用例 2.2  合同条款比对
────────────────────────
参与者      法务人员
前置条件    用户已登录且角色为 legal 或 admin；至少存在两份合同且均已解析条款
后置条件    返回比对差异报告

主事件流
  参与者行为                                  系统行为
  ─────────────────────────────────────────  ─────────────────────────────────────────
  1. 在合同比对页面分别选择合同 A（基准）      2. 展示可选合同列表（已解析条款的合同）
     和合同 B（待审）
  3. 点击"开始比对"                          4. 从 contracts_store.json 读取两份
                                               合同的条款列表
                                             5. 逐条比对条款内容：
                                                形式差异（措辞、标点、格式变更）
                                                实质差异（权利义务变更、责任分配变化）
                                             6. 统计差异总数、形式差异数、实质差异数
                                             7. 对实质差异项，调用 LLM 进行风险评估
                                             8. 返回比对结果（差异统计 + 逐项清单）
  9. 查看比对报告；差异项以红/黄色高亮标注      —

备选事件流
  2a. 合同 B 尚未解析条款 → 系统先执行 parse_clauses()
  2b. 两份合同条款数量差异过大（>5 倍）→ 系统提示"合同结构差异显著，建议人工比对"
  7a. LLM 风险评估失败 → 差异报告仍正常返回，仅实质差异项缺少风险评估标注

五、用例优先级汇总
══════════════════════════════════════

高优先级（核心业务）：
  用户注册与登录、上传合同、AI 合同审查、合同条款比对、法律问题咨询、案件管理与分析、
  LLM 配置管理

中优先级（重要支撑）：
  查看合同状态、法律知识检索、AI 合同生成、知识图谱查询、文书模板管理、用户管理、
  系统参数设置、知识库初始化、查看审计日志、导出合规报告

低优先级（辅助功能）：
  法律计算工具、数据导出、按条件筛选日志、查看操作统计
