# Legal RAG — 法务知识检索增强生成

## 触发条件
- 用户提到"检索法条""查判例""合同条款比对""RAG""向量库""知识库"
- 需要引用具体法律条文编号或判例号
- 合同审查/法律文书生成需要外部知识支撑
- 开发模式触发："初始化知识库""导入数据""构建索引""数据检查"

## 核心约束

**禁止编造**：法律场景对事实准确性要求极高。所有引用必须可追溯到检索结果，不得虚构法条编号、判例号、条款内容。检索不到时明确告知"未找到相关依据"，绝不猜测。

## 工作流程

### 1. 知识库选型
公司内部可用的知识库：
- **法规库**：现行有效的法律法规（按行业/地域/层级分类）
- **判例库**：裁判文书、典型案例、指导性案例
- **合同库**：历史合同模板、条款库、审批记录
- **内部制度**：企业合规手册、风控制度、操作指引

如不确定，建议从"法规库 + 判例库"起步，这是法务 AI 的最小子集。

### 2. 文档预处理
针对法律文档的特点：
- PDF/DOCX 解析时注意双栏排版、页眉页脚（法条编号常在页眉）
- 扫描件需 OCR 预处理，注意印章覆盖区域的文字提取
- 分块策略：按"条"为最小单位（法律文本天然结构），而非固定 token 数
- 保留法条层级路径（第X章 > 第Y节 > 第Z条）作为元数据

### 3. Embedding 与检索
- 使用 legal-domain fine-tuned embedding 模型（如 text-embedding-3-large）
- 混合检索：BM25（精确匹配法条编号）+ 语义检索（近似匹配法律概念）
- 检索后重排序（rerank）：法律概念相似不等于法律适用相同，需要 rerank 模型区分

### 4. 引用格式
返回结果必须包含可验证的引用路径：
```
依据：《民法典》第 584 条（合同编·违约责任）
原文：当事人一方不履行合同义务或者履行合同义务不符合约定...
来源：国家法律法规数据库，2021.1.1 施行
```

### 5. 缓存策略
- 法律法规变更频率低，可长周期缓存（按季度刷新）
- 判例持续更新，按周刷新
- 内部制度/合同库按需实时检索

## 评测标准
- **召回率**：相关法条是否被检索到（优先于精确率，宁可多检不可漏检）
- **引用准确率**：输出的法条编号、内容是否与原文一致
- **时效性**：引用的法条是否为现行有效版本

## 示例对话

用户："帮我查一下，合同违约金过高怎么调整？"

正确的 RAG 流程：
1. 检索《民法典》合同编违约责任相关条款
2. 检索违约金调整的典型判例
3. 输出：
   - 法律依据：《民法典》第 584 条（损失赔偿范围）、第 585 条（违约金调整）
   - 违约金超过造成损失的 30% 可认定为"过分高于"
   - 相关判例：(2023)最高法民终字第XXX号
   - 调整原则：以实际损失为基础，兼顾合同履行情况、当事人过错程度等

## Dev 模式：知识库初始化与数据准备

### 初始化知识库 (init)

创建 `d:\babyhomework\fawu\system\knowledge\` 目录结构：

```
knowledge/
├── laws/
│   ├── civil/              # 民法典、合同法等
│   ├── criminal/           # 刑法相关
│   ├── commercial/         # 公司法、证券法等
│   └── administrative/     # 行政法相关
├── cases/
│   ├── civil/
│   │   ├── contract/       # 合同纠纷判例
│   │   ├── tort/           # 侵权责任判例
│   │   └── property/       # 物权纠纷判例
│   └── commercial/         # 商事判例
├── contracts/
│   ├── templates/          # 合同模板（买卖合同、租赁合同等）
│   └── samples/            # 供审查用的示例合同
└── index_info.json         # 索引元信息文件
```

### 导入法律数据 (import)

支持两种数据格式：

**法律条文** (`laws/*.txt` 或 `laws/*.md`)：
```
# 法律名称
## 施行日期: YYYY-MM-DD
## 状态: 现行有效

### 第X条
条文内容...
```

**判例文书** (`cases/*.json`)：
```json
{
  "case_number": "(2024)沪01民初1234号",
  "title": "案件名称",
  "court": "法院名称",
  "date": "YYYY-MM-DD",
  "case_type": "合同纠纷",
  "verdict": "判决结果摘要",
  "legal_basis": ["民法典第584条"]
}
```

### 构建向量索引 (build_index)

1. 读取 knowledge/ 下所有文件，按条款级(article-level)切分
2. 调用 OpenAI text-embedding-3-large 生成向量
3. 存入 ChromaDB（语义检索层）
4. 建立 Whoosh 索引（BM25 精确匹配层）
5. 更新 index_info.json

### 数据完整性检查 (check_data)

检查知识库数据的完整性：
- 法律条文是否有施行日期
- 判例是否有案号
- 文件编码是否为 UTF-8
- 是否有重复文件
