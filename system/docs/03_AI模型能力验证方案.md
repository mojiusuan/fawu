## 一、验证目标

本方案对智能法务系统的 AI 模型能力进行系统性验证，覆盖以下维度：

1. **法律文本理解**：法条解读、合同条款理解、裁判文书归纳
2. **案例分析**：类案匹配、争议焦点识别、法律依据定位
3. **合同审查**：风险识别覆盖、风险等级判定、修改建议质量

## 二、验证数据集设计

### 2.1 合同审查测试集

#### 测试用例 1：买卖合同违约金条款

```
【输入合同条款】
第六条 违约责任
1. 若甲方逾期付款，每逾期一日，应按逾期金额的千分之五向乙方支付违约金。
2. 若乙方逾期交付，每逾期一日，应按合同总价款的千分之三向甲方支付违约金。
3. 若因乙方交付的货物存在质量问题，甲方有权要求乙方退换或修理，由此产生的费用由乙方承担。

【预期 AI 输出】
风险等级: medium
风险分析: 逾期付款违约金日千分之五（年化 182.5%）明显过高，
         根据民法典第585条，超过造成损失的30%可被认定为过分高于。
         逾期交付违约金日千分之三（年化 109.5%）同样偏高。
法律依据: 《民法典》第585条
修改建议: 建议将违约金调整为日万分之五（年化 18.25%）或
         约定违约金总额不超过合同总价款的20%。
```

#### 测试用例 2：争议解决条款

```
【输入合同条款】
第七条 争议解决
因本合同发生的争议，双方应友好协商解决。协商不成的，任何一方均可向甲方住所地人民法院提起诉讼。

【预期 AI 输出】
风险等级: low
风险分析: 约定甲方住所地法院管辖，对甲方有利，乙方需到甲方所在地应诉。
         此为常见的不对等管辖条款，法律上有效但不公平。
法律依据: 《民事诉讼法》第35条
修改建议: 建议修改为"向被告住所地或合同履行地人民法院提起诉讼"，或约定仲裁。
```

#### 测试用例 3：验收标准模糊条款

```
【输入合同条款】
第四条 交付与验收
甲方应在收到货物后进行验收。验收不合格的，乙方应进行整改直至符合要求。

【预期 AI 输出】
风险等级: medium
风险分析: "符合要求"表述模糊，未明确验收标准和验收期限。
         可能导致双方对是否验收合格产生争议。
法律依据: 《民法典》第620条、第621条
修改建议: 
  - 明确验收期限（如"收到货物后5个工作日内"）
  - 明确验收标准（如"符合国家标准GB/T XXX"）
  - 约定逾期未提出异议视为验收合格
```

### 2.2 法律文本理解测试集

#### 测试用例 4：法条解读

```
【输入问题】
《民法典》第585条关于违约金调整的具体标准是什么？

【预期 AI 回答要点】
- 约定的违约金低于造成的损失的，可请求增加
- 约定的违约金过分高于造成的损失的，可请求适当减少
- "过分高于"的司法实践标准：超过造成损失的30%
- 违约金调整以"实际损失"为基础，兼顾合同履行情况、当事人过错等
- 约定的违约金和定金不能并用
```

#### 测试用例 5：法律概念解释

```
【输入问题】
什么情况下可以单方解除合同？

【预期 AI 回答要点】
- 法定解除情形（民法典第563条）
  - 不可抗力导致合同目的不能实现
  - 对方明确表示或以行为表明不履行主要债务
  - 对方迟延履行，经催告后仍不履行
  - 对方违约导致合同目的不能实现
- 约定解除：当事人约定的事由发生时
```

### 2.3 案例分析测试集

#### 测试用例 6：违约金调整案例

```
【输入案例摘要】
甲公司与乙公司签订买卖合同，约定违约金 150 万元（总价款的 30%）。
后乙公司逾期付款，甲公司实际损失约 50 万元（主要为资金占用利息）。
一审法院判违约金 100 万元，双方均上诉。

【预期 AI 分析】
争议焦点: 违约金约定为总价款 30% 是否过分高于实际损失
法律依据: 民法典第584条、第585条
分析要点:
  - 实际损失约 50 万元
  - 约定违约金 150 万元 = 实际损失的 300%，远超过 130% 标准
  - 法院判决应远低于 150 万元
类似判例: (2023)最高法民终123号
```

#### 测试用例 7：建设工程合同纠纷

```
【输入案例摘要】
XX公司与YY公司签订建设工程合同，总价款 2 亿元。YY公司以原材料上涨
为由要求调价，协商未果后自行停工。XX公司主张违约金 2000 万元。

【预期 AI 分析】
争议焦点: 
  - 原材料上涨是否构成情势变更
  - XX公司实际损失是否达到 2000 万元
法律依据: 民法典第577条、第585条
分析要点:
  - 原材料上涨属于商业风险，不构成情势变更
  - YY公司单方停工构成违约
  - 违约金应与实际损失相当
```

## 三、评估指标体系

### 3.1 合同审查评估

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| 风险识别率 | 正确识别风险数 / 应识别风险总数 | ≥ 85% |
| 风险等级准确率 | 正确判定风险等级数 / 总判定数 | ≥ 90% |
| 法律依据准确率 | 正确引用法条数 / 总引用数 | ≥ 95% |
| 修改建议可操作性 | 专家评分（1-5分） | ≥ 3.5 |
| 审查完整性 | 覆盖的风险类型数 / 预期风险类型数 | ≥ 80% |

### 3.2 法律咨询评估

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| 回答准确率 | 正确回答数 / 总测试问题数 | ≥ 85% |
| 法律依据引用率 | 包含法条引用的回答数 / 总回答数 | ≥ 90% |
| 引用准确率 | 法条编号+内容均正确的引用 / 总引用 | ≥ 95% |
| 幻觉率 | 编造的法条数 / 总引用法条数 | ≤ 3% |
| 回答完整性 | 覆盖预期要点的比例 | ≥ 80% |

### 3.3 案例分析评估

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| 争议焦点识别率 | 正确识别焦点数 / 标定焦点数 | ≥ 80% |
| 法律适用正确率 | 正确适用的法条 / 应适用的法条 | ≥ 90% |
| 类案推荐相关性 | 推荐案例相关的比例 | ≥ 70% |

## 四、评估执行流程

### 4.1 测试执行步骤

```
Step 1: 准备测试数据集（7 个测试用例 +）
Step 2: 人工标注标准答案（法律专家确认）
Step 3: 运行 AI 模型对每个测试用例生成回答
Step 4: 对比 AI 输出与标准答案
Step 5: 计算各指标得分
Step 6: 生成评估报告
Step 7: 根据评估结果调优 Prompt
```

### 4.2 评估脚本

```python
# tests/evaluate_contract_review.py
# 合同审查能力评估脚本

from src.contract_service.agent import contract_agent
from src.contract_service.models import ClauseInfo

async def evaluate_contract_review(test_cases: list[dict]) -> dict:
    """评估合同审查能力"""
    results = {"total": len(test_cases), "pass": 0, "fail": 0, "details": []}

    for tc in test_cases:
        clause = ClauseInfo(
            clause_number=tc["clause_number"],
            content=tc["content"]
        )
        reviewed, _ = await contract_agent.review_contract(
            contract_id="eval_test",
            title="评估测试",
            contract_type=tc["contract_type"],
            clauses=[clause]
        )

        r = reviewed[0]
        checks = {
            "risk_detected": r.risk_level.value != "none",
            "risk_level_match": r.risk_level.value == tc["expected_risk_level"],
            "law_basis_correct": tc["expected_law"] in (r.law_basis or ""),
        }

        passed = all(checks.values())
        if passed:
            results["pass"] += 1
        else:
            results["fail"] += 1

        results["details"].append({
            "test_case": tc["name"],
            "passed": passed,
            "checks": checks,
            "ai_output": {
                "risk_level": r.risk_level.value,
                "risk_analysis": r.risk_analysis,
                "law_basis": r.law_basis,
                "suggestion": r.suggestion,
            }
        })

    results["accuracy"] = results["pass"] / results["total"]
    return results
```

## 五、模型对比实验设计

### 5.1 实验方案

**目标**：对比 Claude-Sonnet-4 与 GPT-4o 在法律任务上的表现差异

**实验变量**：
- 模型类型（Claude-Sonnet-4 vs GPT-4o）
- Temperature（0.0, 0.1, 0.3）

**固定变量**：
- 相同的 Prompt 模板
- 相同的 RAG 检索结果作为上下文

**评估任务**：
- 合同审查 × 10 份合同
- 法律咨询 × 20 个问题
- 案例分析 × 5 个案例

### 5.2 对比实验脚本

```python
# tests/compare_models.py
# 模型能力对比实验

import json
from src.utils.llm_client import LLMClient

async def compare_models(test_cases: list[dict]) -> dict:
    """对比 Claude 和 GPT-4o 的表现"""
    claude = LLMClient(provider="claude")
    gpt4o = LLMClient(provider="openai")

    results = {"claude": [], "gpt4o": []}

    for tc in test_cases:
        for name, client in [("claude", claude), ("gpt4o", gpt4o)]:
            response, usage = await client.generate(
                system_prompt=tc["system_prompt"],
                user_prompt=tc["user_prompt"],
                temperature=0.1,
            )
            results[name].append({
                "test_case": tc["name"],
                "response": response,
                "usage": usage,
                "score": evaluate_response(response, tc["expected"]),
            })

    # 汇总对比
    summary = {
        "claude_avg_score": sum(r["score"] for r in results["claude"]) / len(test_cases),
        "gpt4o_avg_score": sum(r["score"] for r in results["gpt4o"]) / len(test_cases),
        "claude_avg_latency": sum(r["usage"]["latency_ms"] for r in results["claude"]) / len(test_cases),
        "gpt4o_avg_latency": sum(r["usage"]["latency_ms"] for r in results["gpt4o"]) / len(test_cases),
    }

    return summary
```

### 6.1 演示场景 1：合同风险审查

```
展示目的: 验证 AI 对合同条款的风险识别和法律分析能力

演示步骤:
1. 上传买卖合同示例（含违约金过高、管辖约定不明等问题）
2. AI 自动解析合同 → 提取 8 条条款
3. 启动审查 → 逐条分析风险
4. 展示审查报告：
   - 高风险条款 1 条（违约金日千分之五 → 民法典第585条）
   - 中风险条款 2 条（验收标准模糊、管辖约定不对等）
   - 低风险条款 1 条
5. 展示每条条款的法律依据和修改建议
6. 展示审计日志中的决策链路

预期效果: 证明 AI 能准确识别合同风险并给出有法律依据的修改建议
```
