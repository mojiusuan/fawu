## 二、演示场景

### 场景 1：合同审查（约 3 分钟）

**登录**：legal01 / legal01

```
1. 侧边栏选择"合同管理"
2. 先上传一份合同：填写标题、类型、甲乙方、合同全文 → 上传
3. 在合同详情中点击"AI 审查"
4. 观察 AI 逐条分析：
   - 高风险（红色）：违反强制性法律规定
   - 中风险（橙色）：存在争议或模糊表述
   - 低风险（黄色）：轻微瑕疵
   - 无风险（绿色）：合法合规
5. 展开每条条款查看法律依据和修改建议
```

**讲解要点**：Agent 如何构造审查 Prompt · RAG 检索补充法条 · 风险四级分类标准 · 审计日志记录完整决策链

### 场景 2：法律咨询与 RAG（约 2 分钟）

**登录**：任意账号

```
1. 侧边栏选择"法律咨询"
2. 输入"违约金约定多少算过高？怎么调整？"
3. AI 返回结构化回答：
   - 直接回答（引用民法典第585条）
   - 解释"过分高于"的司法标准（超过损失30%）
   - 实操建议（协商/诉讼/仲裁）
4. 点击展开引用的法条查看完整条文
5. 追问"如何申请法院调整违约金？"
6. AI 保持上下文，给出程序性建议
```

**讲解要点**：RAG 混合检索（ChromaDB语义 + Whoosh关键词）· 引用可追溯性 · LLM 安全护栏防止编造法条

### 场景 3：案件中心与分析（约 2 分钟）

**登录**：legal01 / legal01 或 admin / admin

```
1. 侧边栏选择"案件中心"
2. 展示 6 个已创建的案件，覆盖劳动/借贷/合同/人身损害/消费/婚姻六类
3. 点击"张某某劳动纠纷案"查看案件详情
4. 点击关联的分析报告查看：
   - 案情摘要
   - 法律适用分析
   - 相似判例参考
   - 证据收集清单
   - 诉讼费用估算
   - 诉讼时效检查
5. 用下拉菜单切换案件状态（评估中/协商中/诉讼中/已结案）
```

**讲解要点**：CaseAnalyzer 如何从案情中提取要素 · 判例匹配机制 · 分析报告的多维度结构

### 场景 4：多角色差异化（约 2 分钟）

**分别用四个账号登录，对比左侧导航栏：**

| 角色 | 可见功能 |
|------|---------|
| 业务人员 (biz01) | 首页、案件中心、法律咨询、文书模板、计算工具、证据指引 |
| 法务人员 (legal01) | 上栏全部 + 合同管理、案件分析、知识图谱、RPA、数据导出 |
| 管理员 (admin) | 法务全部 + 系统配置（含用户管理、知识库管理、系统参数） |
| 审计员 (audit01) | 首页、案件中心、法律咨询、模板、计算、证据、**审计日志** |

**讲解要点**：RBAC 权限模型 · 角色继承（admin → legal → business）· 审计员独立监督

### 场景 5：审计日志与合规追溯（约 2 分钟）

**登录**：audit01 / audit01

```
1. 侧边栏选择"审计报告"
2. 查看统计卡片：总调用次数、覆盖案件、活跃用户、异常率
3. 按任务类型筛选：contract_review / legal_consultation / rpa / kg_query
4. 按关键词搜索：输入合同编号或用户名
5. 点击某条日志查看审计详情：
   - 操作时间、用户、任务类型
   - 使用模型、Token 消耗、响应延迟
   - 输入输出摘要（SHA256 脱敏）
6. 点击"导出审计报告" → 生成 MD 格式合规报告
```

**讲解要点**：追加写入防篡改 · SHA256 脱敏 · 全链路 AI 决策追溯 · 合规审计能力

### 场景 6：管理员功能（约 2 分钟）

**登录**：admin / admin

```
1. 侧边栏选择"系统配置"
2. LLM 配置：切换提供商（DeepSeek / Claude / OpenAI），调整 temperature
3. API 密钥：输入/更新密钥，点击"测试连接"
4. Neo4j 连接：配置地址，点击"测试图谱连接"
5. 系统参数：端口号、JWT 密钥、日志级别、嵌入模型提供商
6. 知识库管理：查看 ChromaDB/Whoosh 状态 → 点击"初始化/重建"
7. 用户管理：列表展示 4 个用户 → 创建新用户 → 下拉修改角色 → 删除用户
8. 保存配置
```

**讲解要点**：动态配置生效机制 · `.env` 读写 · 用户管理 CRUD · 知识库初始化流程

### 场景 7：知识图谱（约 2 分钟）

**前置条件**：Neo4j Desktop 中 DBMS 已启动

```
1. 用 legal01 登录
2. 侧边栏选择"知识图谱"
3. 搜索框输入"违约" → 返回匹配的法律实体
4. 点击"民法典合同编"实体 → 查看其包含的 Article 子节点
5. 沿关系链路追溯：判例 → 引用 → 法条 → 细化 → 法条
6. 可选：打开 Neo4j Browser (http://localhost:7474)
   MATCH (n)-[r]->(m) RETURN n, r, m LIMIT 50
```

**讲解要点**：8 种实体 + 12 种关系 · 知识图谱本体模型 · Neo4j 可选降级策略

### 场景 8：合同比对与生成（约 2 分钟）

**登录**：legal01 / legal01

```
1. 合同比对：
   - 在比对页面选择合同 A 和合同 B
   - 点击"开始比对"
   - 查看差异报告：形式差异 vs 实质差异，逐条高亮

2. 合同生成：
   - 选择合同类型（如"劳动合同"）
   - 输入甲乙方名称和关键条款要求
   - 点击"生成草稿"
   - 查看 AI 生成的合同草案（标注"AI生成仅供参考"）
```

**讲解要点**：条款逐条比对算法 · LLM 风险评估差异 · 合同生成的安全护栏

### 场景 9：RPA 文档提取（约 1 分钟）

**登录**：legal01 / legal01

```
1. 侧边栏选择"RPA 自动化"
2. 上传合同文件（DOCX/PDF）
3. 点击"提取关键信息"
4. 展示结构化提取结果：
   - 合同标题、甲乙方名称
   - 签署日期、合同金额
   - 关键条款摘要
   - 争议解决方式
```

**讲解要点**：DOCX/PDF 多格式支持 · LLM 结构化信息提取 · RPAAgent 的容错处理

## 三、演示逻辑建议

推荐按以下顺序演示，形成"需求 → 设计 → 实现"的叙事逻辑：

| 顺序 | 场景 | 时长 | 对应论文章节 |
|------|------|------|-------------|
| 1 | 多角色差异化 | 2 分钟 | 需求分析 → 角色模型 |
| 2 | 合同审查 | 3 分钟 | 核心功能 → Agent 设计 |
| 3 | 法律咨询（RAG） | 2 分钟 | 检索增强生成 |
| 4 | 案件中心 | 2 分钟 | 业务流程 |
| 5 | 审计日志 | 2 分钟 | 合规设计 |
| 6 | 管理员功能 | 2 分钟 | 系统管理 |
| 7 | 知识图谱 | 2 分钟 | 数据架构 |
| 8 | 合同比对与生成 | 2 分钟 | Agent 多能力 |
| 9 | RPA 提取 | 1 分钟 | 自动化处理 |

**总计约 18 分钟**，覆盖全部 6 个 Agent 和 4 类用户角色。

## 五、快速恢复环境

```powershell
cd d:\babyhomework\fawu\system
venv\Scripts\activate

# 首次配置
copy .env.example .env
# 填入 API Key

# 安装依赖
pip install -r requirements.txt

# 初始化知识库（首次）
python scripts/init_knowledge_base.py

# 启动
python -m src.main
# → http://localhost:8000
```
